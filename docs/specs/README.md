# 开发规格索引

> 每个特性一个目录：`<feature-slug>/spec.md` + `issues/NN-<中文主题>.md`。
> 规格只定义目标、边界与验收；票是可领取的工作单元，一张票一个可独立验证的交付。
> 与上级 [文档索引](../README.md) 同一套约定：按用途归类、索引集中维护。
> 文件名分工：**`spec.md` 用固定英文名**（工具与 Agent 按惯例直接找它），
> **票名用中文主题**（读的人多、一屏能看懂）。

## 目录约定

```
specs/
├── README.md                    ← 本索引
└── <feature-slug>/
    ├── spec.md                  ← 七段：问题 / 方案 / 用户故事 / 实现决策 / 测试决策 / 范围外 / 备注
    └── issues/
        ├── 01-<中文主题>.md     ← 标题 / 状态 / Blocked by / 缝 / 验收复选框 / 范围外
        └── 02-<中文主题>.md
```

- **规格文件名固定为 `spec.md`**：AI 开发流程与相关工具默认按这个名字找规格；票名用中文主题。
- **票的数字前缀只表顺序**，不代表依赖（依赖写在票的 `Blocked by`）。
- **票的状态**写在票头：`ready-for-agent` / `in-progress` / `done`；完成后勾满验收框并把状态改成 `done`。
- **新增特性**：建 `<feature-slug>/` 目录，先写 `spec.md`（确认测试缝之后再切票），
  再在本文"特性一览"里加一行。
- 文内链接一律相对路径；跨目录引用按层级写（`../../guides/`、`../../../README.md`）。
