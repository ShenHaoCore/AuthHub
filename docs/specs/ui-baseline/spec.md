# 规格：管理后台视觉系统（LeptonX 基线 + 列表与状态表达统一）

- 特性名：`ui-baseline`
- 状态：`done`（三张票均已完成：01 版式与令牌契约、02 列表文字层级、03 状态语义统一）
- 来源：LeptonX Lite 主题源码实测基线 + 后台逐页实测差异清单

## Problem Statement

后台的 8 个页面此前各自演进，同一个"列表"在不同页面上不是同一种东西：

- **密度不一致**：表格正文有的页 14px、有的页 12.5px，行高在 20px / 22.4px 之间摆动；
  切页时视线需要重新适应，扫读成本高。
- **状态表达不一致**：同一个"已停用"，用户页是红色徽章、资源页是琥珀色徽章、客户端页写作"已禁用"；
  "未启用"在一处是灰字、另一处是彩徽章；引用数量与权限点数量用蓝色徽章，和"正向状态"的绿撞语义。
- **与基线偏离**：版式与 ABP LeptonX Lite 的度量对不上（侧栏窄、菜单项圆角、卡片带描边、
  内容区留白偏小），看起来不像同一套产品，也不像该主题下的后台。
- **回归无护栏**：上述都是纯视觉/文案契约，现有测试只断言"页面能打开、关键内容存在"，
  所以同类漂移可以无声地再次发生。

受影响的人：日常在后台做用户/客户端/Scope/资源管理的管理员（靠列表扫读做判断），
以及后续维护后台的开发者与 Agent（没有成文规则可依，只能靠记忆或逐页模仿）。

## Solution

把后台收敛成一套**单一来源的视觉系统**，并用两条契约把"看起来对"变成"可被检查"：

1. **度量与色板集中定义**：颜色与尺寸令牌只有一份，后台与协议页（登录/授权）共用；
   主色、侧栏、圆角、间距、字体全部从这里取，页面不自行发明色号与字号。
2. **列表统一文字层级**：主行 14px/600、次行 12px/灰、正文 14px；等宽字体只换字形不换字号。
   任何页面的列表行高因此一致，纵向滚动与跨页对比不再有视觉跳动。
3. **状态表达按语义分配颜色**：绿＝正常/已完成，琥珀＝待处理/有风险，红＝不可用/失败，
   灰＝分类/计数/非状态说明，蓝只用于身份标签（角色名、"内置"）。同一含义全站同一措辞。
4. **版式对齐 LeptonX Lite 实测度量**：280px 深色固定侧栏、36px 直角菜单项、`#222` 实底选中、
   64px 顶栏（深色壳 + 浅色圆角浮条）、内容区 42/28/56、无描边白卡（8px 圆角、24px 内边距）。
5. **规则写成可指认的文档**：状态语义表、用词表、文字层级与"灰字≠状态"等约定进入后台 UI 文档，
   新增页面/列时照表执行，不再逐页模仿。

## User Stories

1. As a 后台管理员，I want 所有列表的主行与次行字号、行高一致，so that 我切页时不需要重新适应密度，扫读不被打断。
2. As a 后台管理员，I want 每个"启停/验证/锁定"状态都以同一套颜色与措辞出现，so that 我不必逐字读文案就能判断风险。
3. As a 后台管理员，I want 停用类状态统一写作"已停用"并显示为红色，so that 我不会把资源停用误读成"待处理"。
4. As a 后台管理员，I want MFA 这类"开/关"状态始终以徽章呈现（而不是一处徽章、一处灰字），so that 我能一列扫过去看清哪些账号缺少二次验证。
5. As a 后台管理员，I want 引用数量、权限点数量以普通文字呈现而不是彩色徽章，so that 颜色只表达状态，不被数量干扰。
6. As a 后台管理员，I want 空值与零计数用统一的灰色说明（`—`、"未被引用"、"无权限"），so that "没有"和"未启用"在视觉上可区分。
7. As a 后台管理员，I want 客户端类型、授权类型、协议标记等分类信息保持中性灰，so that 蓝色只用来指认角色等身份标签。
8. As a 后台管理员，I want 侧栏、顶栏与卡片严格对齐 LeptonX 基线，so that 后台与项目选定的主题是同一套视觉语言。
9. As a 后台管理员，I want 顶栏在滚动时保持固定、内容列仍有清晰的浮卡边界，so that 长列表滚动时我不丢失"我在哪一页"的上下文。
10. As a 后台管理员，I want 表格在 1440px 宽下不出现挤压换行或操作列错位，so that 常用操作按钮的位置是可预期的。
11. As a 使用登录/授权页的终端用户，I want 登录页与后台共用同一份主色与圆角，so that 从登录到后台的过渡不出现色差。
12. As a 维护后台的开发者/Agent，I want 颜色、尺寸、状态语义各只有一处定义或一张表，so that 我改一个值不会在别的页面留下旧色。
13. As a 维护后台的开发者/Agent，I want 新增状态列时有明确的选色与用词规则，so that 我不需要靠模仿相邻页面来猜。
14. As a 评审者，I want 状态类的渲染结果可被集成测试断言，so that "某页又把停用写成灰字"这类回归会在 CI 里失败。
15. As a 评审者，I want 视觉度量与令牌共享有对应的检查，so that 有人绕过令牌硬编码字号时能被发现。

## Implementation Decisions

### 令牌层

- 颜色、间距、圆角、字体、侧栏/顶栏尺寸集中在一个"设计令牌"样式单元里；后台样式表与协议页样式表都只引用它，不允许各自定义调色板。
- 主色固定为 `#355dff`（取自 LeptonX 主题主色）；侧栏底 `#161616`、选中态 `#222222`、分隔线 `#242424`、次文字 `#9198a5`；内容底 `#f5f5f7`、描边 `#e7e9ec`、正文 `#161616`、次要文字 `#686b6e`。
- 字体栈沿用 IBM Plex Sans（含中文本地回退），**不引入外部字体请求**；CSP 仍为 `script-src 'self'`，所有资源落在站点内。

### 版式基线（LeptonX Lite 实测）

- 侧栏：宽 280px、固定定位、深色底；品牌区 72px（20+32+20）；菜单项 36px 定高、左右 18px、上下 1px、**直角**；hover 只变色不换底；选中＝`#222` 实底 + 白字 + 主色图标。
- 顶栏：外层为随滚动固定的深色壳，内部一条 64px 高的浅色浮条，顶部 `1em` 圆角、1px 描边；内容列整体再以 1px 描边（顶部不描边）包成一张"从深壳里浮起的卡"。
- 内容区：`42px 28px 56px`；卡片无描边、8px 圆角、24px 内边距、`0 0 20px rgba(76,87,125,.02)` 阴影；页标题 24px/500，卡片标题 1.25em/500，卡片头无下边线。
- 窄屏：≤992px 侧栏改为抽屉式并加遮罩；≤720px 内容内边距收缩为 18/14/32。**有意不采用** LeptonX 的 72px 图标栏折叠。

### 组件度量

- 按钮 40px 高、左右 20px、14px/600、8px 圆角；小号 34px。
- 输入/选择/多行输入最小高 40px、内边距 9/14、14px、8px 圆角。
- 表格：正文 14px、单元格 8px、表头 13px/600/次要文字色、无大写变形、无表头底色。
- 徽章：4×7 内边距、11px/700、8px 圆角、**无可见描边**（边框透明只为对齐高度）；顶栏头像 24px；图标按钮 34px、行内操作按钮 30px 描边方块。

### 列表文字层级与溢出

- 三档：主行 14px/600（可叠加等宽）、次行 12px 次要文字、正文 14px。
- **等宽类只改变字族，不改变字号**：它被直接用在单元格和主行上，自带字号会造成"同列不同尺寸"。
- 折叠：长目录类集合（角色、权限、Scope、关联资源）只平铺前两项，其余收进"+N"，展开后接续同一徽章样式。

### 状态语义色板与用词

| 语义 | 修饰 | 用词 |
|------|------|------|
| 正常 / 已完成 | success（绿） | 正常、已验证、已开启、已配置、已启用、成功、已授予的 scope/权限 |
| 待处理 / 临时 / 有风险 | warning（琥珀） | 已锁定、未验证、未开启、CIMD 自动注册、已不在白名单、权限归属被改动 |
| 不可用 / 失败 | danger（红） | 已停用、失败 |
| 分类 / 计数 / 非状态说明 | 裸徽章（灰） | 客户端类型、授权类型、关联资源、协议标记、分组头"N 项" |
| 身份标签 | primary（蓝，唯一专属） | 角色名、"内置" |

- 同一含义全站同一措辞："停用"不再有"已禁用"变体。
- **灰字不是状态**：次要说明层级（12px 灰）只承载说明与空值；是/否型状态必须是徽章。
- **计数不是徽章**：表格计数列用正文文字，为零时用灰字（"未被引用"），只有分组标题旁的数量才用灰徽章。
- 用户账号三态（正常/已锁定/已停用）额外带状态圆点——这是唯一需要"一眼扫过"的列。

### 可访问性与约束

- 徽章颜色永远不是唯一信息载体：每枚徽章都有文字（如"已停用"而非只有色块）。
- 键盘焦点环跟随元素自身圆角（不去覆写圆角值）。
- 所有表格列在 1440×900 下不换行错位；长标识符允许折行，不撑破操作列。

## Testing Decisions

### 测试缝（先确认，再开工）

- **唯一缝**：通过真实 HTTP 管道渲染出的后台页面 HTML + 站点内静态资源内容。
  即用测试宿主在进程内起完整管道，用会话 Cookie 登录后请求各后台页，
  对返回的标记与静态资源做断言。
- 选它的理由：优先已有缝（现有后台测试全部住在这里：逐页渲染断言、协议页与后台共用令牌的断言、
  图标 SVG 契约断言）；是"用户真正看到的东西"所在的最高公开边界；不需要新增浏览器驱动或截图基础设施。
- 它能抓到：状态文案与徽章色调漂移、停用措辞分叉、列表文字层级被内联字号覆盖、令牌不再共享、站外资源回流。
- 它抓不到：具体像素度量（COMPUTED 间距/圆角/颜色值）、视觉对齐与截图差异。这部分留在发布验证阶段用
  固定视口（1440×900）的浏览器实测脚本核对，**不进入 CI**，避免引入易碎的视觉回归套件。

### 好测试的定义

- 读起来像规格：断言"用户列表的 MFA 列对未开启的账号渲染出 warning 徽章与'未开启'文案"，
  而不是断言某个 CSS 类拼接顺序或 DOM 层级。
- 视图重构不导致测试变红：只要行为契约（文案、色调语义、列存在）不变，测试就不该失败。
- 期望值来自独立真源：用规格中的用词表与色板表写字面量，不用页面上同一套逻辑回算期望值。

### 要覆盖的行为

被测模块范围：用户、角色、客户端、Scope、资源、审计六个列表页，加个人页与协议页（登录/授权）；
覆盖项按用词表与色板表推导，不枚举文件。

1. 每个后台列表页中，账号/资源启停状态只有"已停用/已启用"两种文案，且已停用一律危险色。
2. MFA 状态在用户列表与个人页一致：已开启＝success"已开启"，未开启＝warning"未开启"（不再出现灰字或 info 色）。
3. 引用计数与个人页权限点计数不出现在彩色徽章中（要么正文文字，要么灰徽章）。
4. 客户端类型、授权类型、协议标记不使用 success/warning/danger 修饰；角色名与"内置"仍为 primary。
5. 列表单元格类不再把字号写死在等宽/主行/次行类上，字号来自统一层级（可通过静态资源内容断言令牌与类定义）。
6. 协议页与后台仍引用同一份令牌（既有断言必须继续绿）。
7. 所有后台页仍零站外资源引用。

### 测试分层

- 主断言放集成测试（真实管道、临时 SQLite、会话 Cookie），与现有后台测试同构。
- 纯规则校验（如"状态用词只允许白名单"这类跨页一致性）可用一个测试遍历全部后台列表页，
  按页参数化，避免为每个页面复制一份断言。
- 不新增单元测试：本次没有纯领域逻辑，全是对外可观察的渲染契约。

## Out of Scope

- 不改信息架构、页面清单、权限模型、表单流程与任何业务字段；表格列集合不增不减。
- 不做暗色/主题切换、不做品牌换肤；主色与标识视为既定品牌资产。
- 不引入 CDN、外部字体、图标库或任何前端构建链。
- 不重做登录/授权页的版式（只共用令牌与主色）。
- 不实现 LeptonX 的 72px 图标栏折叠侧栏；窄屏继续用抽屉。
- 不做像素级视觉回归（截图 diff）进 CI；不做对比度全量审计（按需用工具抽查）。
- 不再统一表格之外的历史遗留组件（如 Scalar 文档页），除非它们违反"零站外资源"。
- 不补写 ticket 拆解与验收清单（票在同目录 `issues/`，本文件只定义目标与边界）。

## Further Notes

- **基线来自实测，不是印象**：所有度量取自 LeptonX Lite 的 side-menu 布局样式表与 dim 主题样式表
  （280px、36px、`1em` 圆角、`0.5rem` 卡片圆角、`0 0 20px rgba(76,87,125,.02)`、
  `3em 2em 4em` 内边距、`.785em` 徽章字号等），有冲突时以主题源码为准并记录理由。
- **有意保留的三处差异**：字体用 IBM Plex Sans（LeptonX 用 Inter）；窄屏用抽屉而非图标栏；
  面包屑放在顶栏浮条内左侧而非页面内容区顶部。这三项是产品选择，不是遗漏。
- **需要人签字的不可逆点**：主色与品牌标识、状态语义表本身（新增语义或改色映射）、
  以及任何会让既有审计记录被重新解读的措辞调整。其余实现细节由 Agent 自行决定。
- **已知的边界**：度量正确性只在 1440×900 实测过；更宽的 4K 与更窄的移动端仅保证"不错位"，
  不承诺与 LeptonX 逐像素一致。
- **后续可复用**：状态语义表与用词表为此后所有新增列/页面提供判据；若出现新的"非状态但需要强调"的信息，
  优先新增文字层级，而不是新造颜色。
